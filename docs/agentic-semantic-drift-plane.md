# mondayDB Agentic Semantic Drift Plane

## Why this matters

Agentic databases depend on long-term memory, vector search, and procedural
instructions, but stale embeddings or outdated procedures can make an agent act
confidently on the wrong context. The Semantic Drift Plane gives mondayDB a
deterministic way to detect, score, and remediate drift in agent-facing memory
without moving probabilistic behavior into the database engine.

The product trade-off is freshness versus stability:

- **Freshness:** agents should perceive changed boards, docs, automations, and
  procedures quickly enough to avoid stale reasoning.
- **Stability:** re-embedding every change synchronously would add write
  latency, threaten ACID transaction paths, and create noisy background load.
- **Predictability:** drift detection must produce deterministic scores,
  thresholds, audit hashes, and remediation decisions, even when embeddings are
  generated by probabilistic model providers upstream.

This plane therefore runs asynchronously from immutable change events and only
exposes bounded, tenant-scoped drift packets to agents through the Open API.

## Design principles

1. **Tenant isolation first:** every record, index, query, and audit event is
   scoped by `account_id`; HNSW indexes are partitioned or filtered by account
   before similarity search.
2. **Deterministic drift decisions:** mondayDB stores model versions, source
   watermarks, vector hashes, threshold versions, and decision hashes so the same
   inputs replay to the same outcome.
3. **No write-path coupling:** row-store updates commit independently; drift
   detection consumes committed change events and never blocks ACID writes.
4. **Agent-ready perception:** agents receive compact drift cards with source
   references, procedural-memory impact, and safe next actions instead of raw
   unbounded board scans.
5. **Explicit cost guardrails:** every drift scan has a row budget, vector budget,
   recursion limit, and neighbor-impact admission decision.

## TypeScript contracts

```ts
export type DriftSubjectType =
  | "board_item"
  | "column_value"
  | "doc_block"
  | "automation_recipe"
  | "procedure_memory";

export type DriftSeverity = "none" | "low" | "medium" | "high" | "critical";

export interface SemanticDriftSubjectRef {
  account_id: string;
  subject_type: DriftSubjectType;
  subject_id: string;
  board_id?: string;
  workspace_id?: string;
  source_watermark: string;
}

export interface SemanticVectorFingerprint {
  embedding_model: string;
  embedding_dimension: number;
  embedding_hash: string;
  hnsw_partition_key: string; // derived from account_id, never global only
  vector_created_at: string;
}

export interface SemanticDriftMeasurement {
  account_id: string;
  drift_measurement_id: string;
  subject: SemanticDriftSubjectRef;
  previous_fingerprint: SemanticVectorFingerprint;
  candidate_fingerprint: SemanticVectorFingerprint;
  cosine_distance_delta: number;
  lexical_change_ratio: number;
  procedure_dependency_count: number;
  severity: DriftSeverity;
  threshold_policy_version: string;
  decision_hash: string;
  measured_at: string;
}

export interface SemanticDriftRemediationPlan {
  account_id: string;
  remediation_plan_id: string;
  drift_measurement_id: string;
  action:
    | "no_op"
    | "refresh_embedding"
    | "rebuild_subject_context"
    | "flag_procedure_review"
    | "quarantine_agent_memory";
  max_rows_to_touch: number;
  max_vectors_to_write: number;
  requires_human_review: boolean;
  audit_hash: string;
  expires_at: string;

    | "avoid_autonomous_write"

}
```

## SQL schema

```sql
CREATE TABLE agentic_semantic_drift_measurements (
  account_id BIGINT NOT NULL,
  drift_measurement_id UUID NOT NULL,
  subject_type TEXT NOT NULL,
  subject_id TEXT NOT NULL,
  board_id BIGINT,
  workspace_id BIGINT,
  source_watermark TEXT NOT NULL,
  previous_embedding_model TEXT NOT NULL,
  previous_embedding_hash TEXT NOT NULL,
  candidate_embedding_model TEXT NOT NULL,
  candidate_embedding_hash TEXT NOT NULL,
  cosine_distance_delta DOUBLE PRECISION NOT NULL,
  lexical_change_ratio DOUBLE PRECISION NOT NULL,
  procedure_dependency_count INTEGER NOT NULL DEFAULT 0,
  severity TEXT NOT NULL,
  threshold_policy_version TEXT NOT NULL,
  decision_hash TEXT NOT NULL,
  measured_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (account_id, drift_measurement_id)
);

CREATE INDEX idx_semantic_drift_subject
  ON agentic_semantic_drift_measurements (
    account_id,
    subject_type,
    subject_id,
    measured_at DESC
  );

CREATE INDEX idx_semantic_drift_board_severity
  ON agentic_semantic_drift_measurements (
    account_id,
    board_id,
    severity,
    measured_at DESC
  )
  WHERE board_id IS NOT NULL;

CREATE TABLE agentic_semantic_drift_remediation_plans (
  account_id BIGINT NOT NULL,
  remediation_plan_id UUID NOT NULL,
  drift_measurement_id UUID NOT NULL,
  action TEXT NOT NULL,
  max_rows_to_touch BIGINT NOT NULL,
  max_vectors_to_write BIGINT NOT NULL,
  requires_human_review BOOLEAN NOT NULL,
  audit_hash TEXT NOT NULL,
  expires_at TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (account_id, remediation_plan_id),
  FOREIGN KEY (account_id, drift_measurement_id)
    REFERENCES agentic_semantic_drift_measurements (
      account_id,
      drift_measurement_id
    )
);

CREATE INDEX idx_semantic_drift_remediation_measurement
  ON agentic_semantic_drift_remediation_plans (
    account_id,
    drift_measurement_id,
    created_at DESC
  );

CREATE TABLE agentic_semantic_drift_audit_events (
  account_id BIGINT NOT NULL,
  audit_event_id UUID NOT NULL,
  drift_measurement_id UUID,
  remediation_plan_id UUID,
  event_type TEXT NOT NULL,
  actor_type TEXT NOT NULL,
  actor_id TEXT NOT NULL,
  previous_audit_hash TEXT,
  audit_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (account_id, audit_event_id)
);

CREATE INDEX idx_semantic_drift_audit_chain
  ON agentic_semantic_drift_audit_events (
    account_id,
    created_at DESC,
    audit_hash
  );
```

For pgvector/HNSW compatibility, the embedding table remains separate from the
measurement table so vectors can be sharded independently:

```sql
CREATE TABLE agentic_semantic_drift_vectors (
  account_id BIGINT NOT NULL,
  subject_type TEXT NOT NULL,
  subject_id TEXT NOT NULL,
  embedding_model TEXT NOT NULL,
  embedding vector(1536) NOT NULL,
  embedding_hash TEXT NOT NULL,
  source_watermark TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (account_id, subject_type, subject_id, embedding_model)
);

CREATE INDEX idx_semantic_drift_vectors_hnsw
  ON agentic_semantic_drift_vectors
  USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);
```

Production deployments should physically partition
`agentic_semantic_drift_vectors` by `account_id` hash or account shard. A global
HNSW index without a tenant-pruning path is not acceptable for multi-tenant
mondayDB workloads.

## Execution flow

1. Row-store or document updates commit normally and emit immutable change events
   with `account_id`, subject references, and source watermarks.
2. A drift worker batches committed events by `(account_id, subject_type)` and
   computes lexical deltas plus candidate embedding hashes.
3. The worker compares the prior and candidate fingerprints using deterministic
   thresholds from a versioned policy table.
4. The planner writes a measurement, remediation plan, and audit event in one
   transaction.
5. Agents only see perception cards or bounded remediation APIs. They do not get
   direct permission to recursively rebuild memory across a board.

## Guardrails for autonomous agents

- Require `account_id` on every API input and every storage predicate.
- Reject refresh requests without an exact `subject_type`, `subject_id`, and
  `source_watermark`.
- Clamp `limit` to 100 cards and require cursor pagination for larger review
  workflows.
- Allow at most one remediation hop from measurement to plan to execution unless
  a human-approved procedure memory explicitly raises the limit.
- Store `decision_hash = sha256(canonical_measurement_inputs)` and
  `audit_hash = sha256(previous_audit_hash || canonical_event)` for replay.
- Route high or critical procedure-memory drift to human review before agents can
  use the affected procedure for autonomous writes.

## Performance check for 1M+ row boards

Potential full table scan risks:

- Querying drift measurements by `board_id` without `account_id`.
- Searching vector drift candidates without an account partition or tenant shard.
- Asking for all subjects on a board after a broad automation change.
- Computing lexical deltas by reading current board rows instead of consuming the
  committed change-event payload.

Mitigations:

- Composite indexes always start with `account_id`.
- Board-level reviews must use `(account_id, board_id, severity, measured_at)`
  and cursor pagination.
- Vector scans must prefilter by account shard and cap `topK`.
- Backfills run through workload admission with per-account row and vector
  budgets.
- Columnar summaries may estimate impacted subjects, but row-store remediation
  uses exact subject refs and source watermarks.

## How an LLM or agent perceives this data

An agent should see the drift plane as a trust signal, not as hidden magic. A
perception card can be rendered as:

```json
{
  "semantic_tags": ["stale-memory-risk", "procedure-review-needed"],
  "agent_summary": "The linked procedure changed materially after the last embedding. Avoid autonomous writes until refreshed.",
  "safe_actions": [
    "request_context_refresh",
    "ask_human_to_review_procedure"
  ],
  "source_watermark": "rowlog:account/123:8492201"
}
```

This keeps the database deterministic while giving agents a clear, bounded view
of when memory is fresh enough to use.
